# Требования к онлайн-заявкам на депозиты и кредиты банка «Стандарт»

| Код | Требования | Комментарий |
|-----|------------|-------------|
| F | **Функциональные (Functionality)** | |
| F1 | На сайте новый клиент видит депозиты с актуальными ставками и подаёт заявку, указав Ф. И. О. и телефон. | Заявка поступает в систему кол-центра банка. Оператор изучает её, звонит клиенту и может предложить особые условия. Для идентификации клиент приходит в отделение. |
| F2 | В интернет-банке клиент видит доступные депозиты, общие и персональные ставки. Для подачи заявки он выбирает счёт, указывает сумму и подтверждает операцию СМС-кодом. | Персональная ставка относится к конкретному клиенту. Общие ставки должны совпадать на сайте и в интернет-банке. |
| F3 | Депозитный и кредитный бэк-офисы работают с единым набором актуальных ставок. Доступ к исходным данным для расчёта разграничен по ролям. | Сегодня ставки хранятся в XLS-файлах. Кредитный отдел передаёт оценку риска, депозитный использует её для расчёта спецставки. Хранение ставок в АБС — вариант для MVP. |
| F4 | В MVP менеджер бэк-офиса обрабатывает заявку и подтверждает условия депозита в АБС. Клиент получает СМС при подтверждении ставки и ещё одно при открытии депозита. | Каждое уведомление соответствует отдельному событию. СМС-код при подаче заявки выполняет другую функцию — подтверждает действие клиента. |
| F5 | Сайт и интернет-банк показывают актуальные кредитные предложения. На сайте новый клиент может подать заявку по Ф. И. О. и телефону. | Источник полных условий кредита — Кредитный конвейер. |
| F6 | Если новый клиент указал на сайте паспортные данные, он сразу получает предварительное решение по кредиту. После подачи заявки сайт инициирует отправку СМС о визите в отделение для идентификации и получения кредита. | Для предварительного решения система скоринга использует только сведения БКИ. Паспортные данные нужны для этого сценария, а базовую заявку можно подать без них. |
| F7 | В отделении менеджер через АБС продолжает работу с заявкой, по которой клиент уже получил предварительное решение на сайте. Если заявки нет, менеджер создаёт новую. | При переходе с сайта в отделение должны сохраниться заявка и принятое по ней решение. |
| F8 | В интернет-банке клиент может увидеть предодобренное предложение с рассчитанной суммой. При подаче кредитной заявки он указывает данные и счёт зачисления, затем подтверждает отправку СМС-кодом. | Предложение опирается на ранее выполненный скоринг. Если обстоятельства изменились, после подачи заявки проводят повторную упрощённую оценку. |
| F9 | При изменении статуса кредитной заявки клиент получает СМС. | Основание для отправки — смена статуса заявки в банке. Для доставки у банка есть СМС-шлюз телеком-оператора. |
| U | **Удобство использования (Usability)** | |
| U1 | Экраны выбора продукта, подачи и подтверждения заявки используют принятую в банке дизайн-систему. | На сайте и в интернет-банке клиент видит привычные цвета, элементы бренда и формы ввода. |
| R | **Надёжность (Reliability)** | |
| R1 | Сервисы обоих направлений, включая интернет-банк, должны работать 24/7 с целевой доступностью 99,9%. | При отказе основного ЦОД интернет-банк должен выдерживать требуемую нагрузку в резервном. Сейчас рабочая группа серверов находится в одном ЦОД. Достижимость цели при переключении ещё не подтверждена. |
| R2 | Повторная отправка уже принятой заявки после сбоя связи должна возвращать ту же заявку. | **Дополнительное требование.** Банк может принять заявку до того, как клиент увидит ответ. Повторная попытка не должна приводить к двум депозитам или параллельному рассмотрению одного кредита. |
| P | **Производительность (Performance)** | |
| P1 | Для пользовательских операций нужен отклик за миллисекунды, включая загрузку справочников. | Сейчас при платежах некоторые справочники загружаются дольше секунды. Численный предел и нагрузку для проверки нужно согласовать. Время ответа интерфейса измеряется отдельно от ожидания решения сотрудника. |
| P2 | Сотрудники обрабатывают кредитные заявки по предодобренным предложениям в тот же рабочий день. | Текущий суточный обмен АБС с Кредитным конвейером может доставить заявку лишь на следующий день. Для таких заявок нужен путь передачи, независимый от расписания выгрузки. |
| P3 | Предрасчёт предодобренных предложений должен обходиться без дополнительной нагрузки на действующую систему скоринга. | В рабочие часы ресурсы скоринга нужны для решений по поступающим заявкам. |
| P4 | Сервисы, поддерживающие горизонтальное масштабирование, должны равномерно распределять запросы между экземплярами и выдерживать нагрузку при переключении между ЦОД. | Кредитный конвейер и скоринг уже поддерживают горизонтальное масштабирование и работу 24/7. Для интернет-банка требуемую пропускную способность ещё предстоит проверить. Ограничение АБС приведено в +R2. |
| S | **Поддерживаемость (Supportability)** | |
| S1 | Подготовить документацию, по которой команды банка смогут расширять депозитный и кредитный процессы. | Описать источники ставок и условий, обмен заявками и статусами, а также ответственность систем за подтверждения и уведомления. |
| S2 | Сопровождение должно позволять проследить принятую заявку от канала подачи до результата обработки в банке. | **Дополнительное требование.** Если клиенту не пришло СМС, поддержке важно отличить задержку обработки заявки от сбоя доставки сообщения. |
| +R | **+ Ограничения (Restrictions)** | |
| +R1 | Шифровать трафик с данными клиента при передаче с сайта и в интернет-банке. | Требование распространяется в том числе на Ф. И. О., телефон, паспортные данные и реквизиты счёта. |
| +R2 | При проектировании онлайн-подачи учитывать предел нагрузки АБС. Для нового процесса желательно избежать прямых вызовов API АБС из интернет-банка. | База Oracle уже перегружена и масштабируется только вертикально. Интернет-банк сейчас обращается к БД АБС напрямую для платежей и текущих счетов. Перенос этой схемы на онлайн-заявки увеличит нагрузку. |
| +R3 | Сохранить существующую частоту обмена между БД АБС и Кредитного конвейера — раз в сутки. | Учащать выгрузку нельзя. Это ограничение существенно для срока обработки предодобренных заявок (P2). |
| +R4 | Для СМС-подтверждения в интернет-банке предпочтительна реализация силами команды банка без изменения ядра платформы. | Существующий СМС-функционал находится в ядре монолита на .NET Framework 4.5. Изменения ядра зависят от подрядчика. |
| +R5 | Предпочитать технологии, которые уже используются в банке. Новые компоненты должны быть совместимы с действующими платформами и по возможности знакомы командам. | В интернет-банке используется MS SQL, в АБС и Кредитном конвейере — Oracle. Конвейер работает на Camunda с Java-обработчиками, скоринг предоставляет REST API на Python/Flask. |
| +R6 | Если для обмена нужны очереди сообщений, предпочтительна Kafka. Действующая платформа интернет-банка несовместима с ней напрямую. | Выделение депозитной функции в отдельный сервис — возможный вариант. Переход всего интернет-банка на микросервисы выходит за рамки MVP. |
